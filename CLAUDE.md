# CLAUDE.md — working notes for Claude in this repo

`claude-ableton` is a **Claude plugin** (a Node/TypeScript MCP server) that drives
Ableton Live 12 via a bundled, pinned fork of AbletonOSC. It's distributed
GitHub-natively: this one repo is **both the marketplace and the plugin**.

## Layout
- `src/*.ts` — the server. `tools.ts` (all 101 MCP tools), `osc.ts` (hand-rolled
  OSC over `dgram`), `chords.ts` (voice-leading), `installer.ts` (Option-B Remote
  Script installer), `index.ts` (entry), `server.ts`, `context.ts`, `constants.ts`,
  `types.ts` (shared `Note`/`RhythmStep`/`AutomationStep` shapes).
- `dist/index.js` — **committed** esbuild bundle (zero runtime deps). This is what
  the plugin actually runs.
- `vendor/AbletonOSC/` — **committed** pinned Remote Script, generated by
  `scripts/vendor-remote-script.mjs` (clones the fork at `PINNED_REF`).
- `.claude-plugin/plugin.json` — plugin manifest. **Declares the MCP server inline**
  (`mcpServers.ableton` → `node ${CLAUDE_PLUGIN_ROOT}/dist/index.js`) and holds the
  **version**.
- `.claude-plugin/marketplace.json` — marketplace; the plugin's `source` is `"./"`.
- `scripts/` — `build.mjs` (esbuild), `vendor-remote-script.mjs`,
  `integration-test.mjs` (live 101-tool test), `list-tools.mjs`, `smoke-send.ts`.

## Release runbook — do this when asked to "do a release"
1. Make changes under `src/`.
2. `npm run typecheck && npm run build` — rebuilds the **committed** `dist/index.js`.
3. If the AbletonOSC fork changed: set `PINNED_REF` in
   `scripts/vendor-remote-script.mjs` to the new fork commit, run `npm run vendor`,
   and stage `vendor/AbletonOSC/`.
4. **Bump `version` (semver) in BOTH `.claude-plugin/plugin.json` AND
   `package.json`** — keep them identical. Claude reads `plugin.json`'s version;
   users only receive auto-updates when this string changes. (If `version` were
   omitted, Claude would fall back to the git commit SHA instead.)
5. Commit everything, **including the rebuilt `dist/index.js`** (and `vendor/` if it
   changed).
6. Tag and push: `git tag -a vX.Y.Z -m "…" && git push origin main && git push origin vX.Y.Z`.
   (The git tag is for humans; Claude's update logic uses `plugin.json`'s version.)
7. Users on auto-update get it next startup → prompted to run `/reload-plugins`.
   Auto-update is **off by default** for third-party marketplaces (each user
   enables it per-marketplace via `/plugin` → Marketplaces → Enable auto-update);
   manual update is `/plugin marketplace update claude-ableton` → `/reload-plugins`.

## Gotchas (already learned — don't rediscover)
- The committed `dist/index.js` MUST be the **esbuild bundle** (plugins don't run
  `npm install` at install time). Always `npm run build` before committing a release.
  Runtime deps are bundled in, so they live in `devDependencies`.
- **Do NOT add a repo-root `.mcp.json`** — Claude auto-detects it as a "LOCAL DEV"
  project MCP server, creating a confusing duplicate. The server is declared
  **inline in `plugin.json`** instead.
- marketplace.json plugin `source` must be `"./"`. A bare `"."` is rejected with
  "source type your Claude Code version does not support".
- Keep AbletonOSC's MIT license + attribution to **Daniel Jones / ideoforms**
  (`vendor/AbletonOSC/LICENSE.md`). Do not add a prior-art credit to `ableton-mcp`
  (removed at the owner's request).

## Testing against live Ableton
- `node scripts/integration-test.mjs` drives all 101 tools (assertions + cleanup).
  Requires: **OSC port 11001 free** (only one server can bind it — stop any other
  running instance/plugin first), Live running with **AbletonOSC** selected as a
  Control Surface, and a scratch set open.
- To test the actual plugin install locally, drive the bundled Claude Code CLI at
  `~/Library/Application Support/Claude/claude-code/<version>/claude.app/Contents/MacOS/claude`
  with an isolated `CLAUDE_CONFIG_DIR` so you don't touch the real config.

## Constraints
- macOS-first. Localhost-only (OSC on 127.0.0.1:11000/11001). The repo is **public**.
